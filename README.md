# Ship Classifier — Naval vs Civilian

End-to-end mini computer-vision project: upload a vessel photo in the browser,
get a Naval/Civilian prediction back from a lightweight MobileNetV2 model.
Inference runs **entirely client-side** (onnxruntime-web/WASM) — there's no
server or serverless function, so the whole app is a static site deployable
anywhere (Netlify, GitHub Pages, S3, etc.) and works offline once loaded.

## Architecture

```
ship-classifier/
  data/train/{naval,civilian}/   <- your labeled training images (not committed)
  data/val/{naval,civilian}/     <- your labeled validation images (not committed)
  scripts/
    generate_dummy_data.py       <- procedural placeholder data for pipeline smoke-tests
    train.py                     <- trains MobileNetV2 classifier (PyTorch)
    export_onnx.py                <- exports trained model to ONNX
    copy_ort_assets.js            <- (postinstall) copies the onnxruntime-web WASM
                                      runtime from node_modules into public/ort/
  checkpoints/                    <- training checkpoints (.pth, gitignored)
  public/
    model/
      ship_classifier.onnx        <- exported model, served statically (committed, ~9MB)
      classes.json                <- class label order (auto-generated, committed)
    ort/                          <- onnxruntime-web WASM runtime (gitignored,
                                      regenerated by `npm install`)
  src/
    classifier.js                 <- loads the ONNX model in-browser and runs inference
    App.jsx, api.js*, ...          <- React upload UI (Vite)
  netlify.toml                    <- static build config (no functions needed)
```

## 1. Collect and label data

Put images into:
```
data/train/naval/*.jpg
data/train/civilian/*.jpg
data/val/naval/*.jpg
data/val/civilian/*.jpg
```
Aim for 300-1000+ images per class to start; balance the classes. An 80/20
train/val split is a reasonable default.

Don't have real labeled images yet? Generate a small procedural placeholder
dataset to smoke-test the whole pipeline first:
```bash
python scripts/generate_dummy_data.py --data_dir data --train_per_class 60 --val_per_class 15
```
This draws simple grey/angular "naval-ish" and colorful/boxy "civilian-ish"
shapes — enough to verify training → export → in-browser inference works,
but **not real training data**. Expect it to overfit (great train accuracy,
~50% i.e. chance-level val accuracy) since it's random-init on a handful of
synthetic images with no genuine visual signal — replace the `data/` folders
with real photos before trusting any prediction.

## 2. Train the model

```bash
pip install -r scripts/requirements.txt --break-system-packages
python scripts/train.py --data_dir data --epochs 15
```

This fine-tunes a pretrained MobileNetV2 and saves the best checkpoint (by
validation accuracy) to `checkpoints/ship_classifier.pth`. Pass
`--no_pretrained` to skip downloading ImageNet weights (useful for offline
smoke tests with dummy data — accuracy will suffer without pretrained
features).

## 3. Export to ONNX

```bash
python scripts/export_onnx.py
```

Reads `checkpoints/ship_classifier.pth` and writes
`public/model/ship_classifier.onnx` + `public/model/classes.json` (class
label order) directly into the folder the frontend serves statically.

## 4. Run locally

```bash
npm install    # also fetches the onnxruntime-web WASM runtime into public/ort/
npm run dev
```

Open the printed local URL — the model loads and runs fully in the browser,
no backend process required.

## 5. Deploy on Netlify (or any static host)

1. netlify.com → "Add new site" → "Import an existing project" → pick your
   GitHub repo.
2. Build command: `npm run build`
3. Publish directory: `dist`
4. Deploy. `npm install`'s postinstall step regenerates `public/ort/` during
   Netlify's build, and `public/model/*` is committed to the repo, so no
   extra configuration is needed — this is a static site.

## Notes

- The model runs via `onnxruntime-web`'s WASM backend — no native binaries,
  no serverless cold starts, and it's portable to any static host.
- To extend beyond two classes (e.g., add "Auxiliary", "Fishing"), just add
  folders under `data/train` and `data/val` — the training script infers
  classes automatically from folder names.
- If you want to fold in AIS-derived features later (AIS presence/absence,
  MMSI type, behavior patterns), the cleanest path is a second small
  classifier or rule-based score that you combine with the image model's
  confidence before showing a final verdict.
